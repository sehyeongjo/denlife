# denlife

모바일용 다중 통화 가계부입니다. Next.js App Router + React + TypeScript를 사용하며, 거래 내역과 등록 당시 환율을 Neon PostgreSQL에 저장합니다. 회원가입 없이 공통 비밀번호로 접속하고 같은 가계부를 여러 기기에서 사용할 수 있습니다.

## 실행

Node.js 22 이상에서 실행하세요. 새로 내려받은 경우 환경변수 파일을 먼저 만드세요.

```bash
cp .env.example .env.local
npm install
```

`.env.local`에 다음 값을 설정합니다. 실제 비밀번호와 연결 문자열은 Git에 올리지 않습니다.

```dotenv
APP_PASSWORD=test
DATABASE_URL=postgresql://USER:PASSWORD@YOUR-HOST-pooler.neon.tech/neondb?sslmode=require
# 선택: 스키마 준비에 사용할 직접 연결 주소
DATABASE_URL_UNPOOLED=postgresql://USER:PASSWORD@YOUR-HOST.neon.tech/neondb?sslmode=require
```

```bash
npm run db:setup
npm run dev
```

http://localhost:3000 에서 `APP_PASSWORD`로 접속하세요. 현재 로컬 접속 비밀번호는 `test`입니다. 같은 Wi-Fi의 휴대폰에서는 `http://<컴퓨터의 로컬 IP>:3000`으로 접속할 수 있습니다.

`db:setup`은 가계부 전용 `denlife_ledgers` 테이블과 기본 원장을 준비합니다. 기존 테이블과 기존 원장은 변경하지 않으므로 다시 실행해도 기존 내역을 초기화하지 않습니다. `DATABASE_URL_UNPOOLED`가 있으면 초기화에 사용하고, 앱은 `DATABASE_URL`을 사용합니다. PG/POSTGRES 접두사의 별도 환경변수는 사용하지 않습니다.

## 화면과 기능

- 모바일 단일 열 화면, 홈 / 내역 / 설정 하단 메뉴
- 본문·입력칸 16–18px, 주요 금액 30–42px, 주요 버튼 48–58px
- 월별·연도별 지출·수입·잔액, 최근 내역, 검색, 수입·지출 필터
- 설정 또는 내역 입력 중 카테고리 추가, 여러 카테고리 선택 필터
- 카테고리별 원형 그래프, 금액·비중(%) 표시: 전체/지출 선택 시 지출, 수입 선택 시 수입 비중
- 수입·지출 선 그래프: 월별 보기의 일별 추이, 연도별 보기의 1~12월 추이
- 그래프를 터치하거나 상세 기간을 선택해 해당 일·월의 금액 확인
- 거래 추가·수정·삭제 후 DB 확인 응답을 받은 뒤 화면에 반영
- 기본 DKK, KRW / USD / JPY / EUR 및 다른 ISO 통화 추가
- 합계 표시 통화 변경, 설정에서 전체 기간의 통화별 잔액 확인
- 등록 환율 보관, 수동 환율 입력, 저장 환율 확인
- 상단 새로고침으로 다른 기기에서 바뀐 내역 조회
- 서버의 최신 내역 JSON 백업, 비밀번호 접속 및 잠그기

## 기존 브라우저 내역 옮기기

이전 버전의 `denlife.ledger.v1` 내역이 있으면 **DB로 옮기기** 안내가 표시됩니다. 원본 백업 후 이 버튼을 누르면 서버 원장에 없는 거래만 추가합니다. 같은 ID의 거래가 이미 있으면 서버의 기록을 유지합니다. 통화 목록도 함께 병합합니다.

원본 localStorage 데이터는 삭제하지 않습니다. DB 저장이 확인된 뒤 이관 완료 표시만 남깁니다. 로그인 비밀번호 변경이나 잠그기는 DB 기록과 로컬 원본에 영향을 주지 않습니다. 샘플 데이터는 자동으로 표시하거나 DB에 넣지 않습니다.

## 비밀번호 설정

`APP_PASSWORD`는 서버 전용 환경변수입니다. 원하는 값으로 변경한 뒤 로컬 서버를 재시작하거나 Vercel에서 **Redeploy**하세요. Vercel 환경변수는 로컬 `.env.local`에 자동으로 동기화되지 않습니다. `NEXT_PUBLIC_` 접두사는 붙이지 않습니다.

- 비밀번호 검증은 `/api/auth/login`에서 수행합니다.
- 성공 시 7일 유효한 HMAC 서명 세션 쿠키를 발급합니다. HttpOnly / SameSite=Lax이며 프로덕션에서는 Secure를 사용합니다.
- 가계부 페이지와 원장·환율 API 모두 서버에서 세션을 검사합니다.
- 환경변수가 없으면 접속을 차단하며 기본 프로덕션 비밀번호는 없습니다.
- 비밀번호 변경 후 재배포하면 기존 세션도 무효화됩니다. 열린 화면은 새로고침 후 다시 접속하세요.
- 같은 서버 인스턴스에서 1분에 5회까지 접속을 시도할 수 있습니다. 인스턴스 간 공유 제한이 필요하면 Vercel WAF 등을 설정하세요.
- 같은 비밀번호로 접속한 사용자는 하나의 원장을 공유합니다. 사용자별 계정과 원장 분리는 없습니다.

## DB 저장과 충돌 방지

앱은 `/api/ledger`를 통해서만 DB에 접근합니다. 연결 문자열은 서버에서만 사용하고 브라우저 응답이나 소스 코드에 포함하지 않습니다. 응답과 DB 조회는 캐시하지 않습니다.

`denlife_ledgers`의 `main` 행에 버전 1 원장을 JSONB로 저장합니다. 원래 금액·통화·날짜·카테고리·메모·등록 시각과 환율표 전체를 유지합니다. `revision`과 `updated_at`도 보관합니다.

사용자 카테고리는 원장 안의 `customCategories`에 저장합니다. 이 필드가 없는 기존 원장과 백업은 빈 배열로 보완해서 읽으므로 별도 DB 마이그레이션은 필요하지 않습니다. 카테고리는 설정이나 거래 입력 화면에서 추가할 수 있고, 수입·지출 모두에 사용할 수 있습니다. 카테고리 이름은 1~30자이며 중복 이름은 허용하지 않습니다.

내역 화면의 검색·카테고리 필터는 내역과 그래프에 함께 적용됩니다. 여러 카테고리를 선택하면 선택한 카테고리 합계를 분모로 비중을 계산하며, 모두 해제하거나 ‘모든 카테고리’를 누르면 전체를 표시합니다. 선 그래프는 수입·지출을 함께 보여주고, 유형 필터는 거래 목록과 원형 그래프에 적용됩니다. 모든 그래프는 거래별 등록 환율과 상단의 표시 통화를 사용합니다. 환산 불가 내역은 계산에서 제외하고 건수를 표시합니다.

저장 요청은 읽었던 `revision`을 포함하며, 서버는 `WHERE revision = ...` 조건으로 원자적으로 갱신합니다. 다른 기기가 먼저 저장했다면 409를 반환하고 최신 내역을 불러옵니다. 작성 중인 입력은 유지하므로 최신 내역을 확인한 뒤 다시 저장하세요. 기존 거래의 등록 시각·환율 변경은 서버에서도 거부합니다.

DB 장애 시 브라우저 저장 방식으로 조용히 전환하지 않습니다. 저장 실패나 충돌을 표시하고 성공이 확인된 내역만 화면에 반영합니다. 서버리스 요청 한도에 맞춰 원장 저장 요청은 최대 4MB입니다. 이 크기에 가까워지면 거래별 저장과 기간별 조회로 확장해야 합니다.

## 환율과 금액

`GET /api/rates`는 [Frankfurter v2](https://frankfurter.dev)의 DKK 기준 전체 환율을 조회합니다. 등록 직전에 최신 일별 고시값을 다시 조회하고, 통화별 고시일·조회 시각·환율표 전체를 해당 거래에 저장합니다. 과거 날짜의 거래도 **거래 날짜가 아닌 등록 시점 기준**입니다.

금액은 통화의 최소 단위 정수입니다. DKK / USD / EUR는 소수점 2자리, KRW / JPY는 정수 단위이며 `Intl.NumberFormat`의 정밀도를 따릅니다. 각 거래를 저장된 환율로 환산하고 최소 단위로 반올림한 뒤 합산합니다. 수정·동기화·이관 후에도 최초 환율을 유지합니다.

추가 통화가 과거 환율표에 있으면 바로 환산합니다. 필요한 환율이 없는 거래는 환산 합계에서 제외하고 제외 건수를 표시합니다. 원래 금액은 유지합니다. 설정의 현재 참고 환율은 기존 거래의 계산에 사용하지 않습니다. 거래 내용과 금액은 외부 환율 API에 보내지 않습니다.

## Vercel

Git 저장소: `https://github.com/sehyeongjo/denlife.git`

1. Framework Preset은 **Next.js**, Root Directory는 프로젝트 루트, Build Command는 `npm run build`로 설정합니다.
2. Production 환경변수에 `APP_PASSWORD`, `DATABASE_URL`을 설정합니다. Neon 통합이 `DATABASE_URL`을 추가했다면 그대로 사용합니다. Preview에도 필요한 환경변수를 지정하세요.
3. 사용할 DB에 `npm run db:setup`을 한 번 실행합니다. 제공된 DB에는 이미 실행했습니다.
4. 코드를 push해 배포합니다. 환경변수만 수정한 경우에도 Redeploy가 필요합니다.

## 주요 파일

- `src/lib/ledger.ts`: 거래 타입, 금액·환율 계산, 원장 검증
- `src/lib/ledger-sync.ts`: 서버 상태 검증, 로컬 이관 병합
- `src/lib/database.ts`: Neon 연결, 스키마 준비, 버전 기반 원자적 저장
- `src/app/api/ledger/route.ts`: 인증된 원장 읽기·저장 API
- `src/components/ledger-app.tsx`: 모바일 화면, DB 동기화와 로컬 이관
- `src/lib/auth.ts`, `src/app/api/auth/`: 비밀번호·세션 검증
- `scripts/setup-db.ts`: DB 준비 명령
